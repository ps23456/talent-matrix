Design analysis & direction

Your current UI (static/index.html) is solid and functional: Syne + DM Sans, indigo/violet gradients, navy shells, and JetBrains Mono for scores. Per the frontend-design skill, that palette reads as generic “AI SaaS.” Below is a recruiter-appropriate alternative that keeps your layout and flows intact.

What works today

  • Clear information hierarchy (sidebar → topbar → panels → cards)
  • Semantic verdict colors (TOP / HOLD / REJECT)
  • Dark + light theme with CSS variables
  • Monospace for scores, badges, and logs — correct for data density
  • Staggered card animations on match results

What to change (intentionally)

  • Accent: Drop #6366F1 / #8B5CF6 gradients → copper (#C45C3E) for brand actions; teal (#2DD4BF) for AI/signal metrics
  • Typography: Syne + DM Sans → Fraunces (headlines) + IBM Plex Sans (UI body) + IBM Plex Mono (data)
  • Surfaces: Cool blue-grays → warm charcoal / cream paper (light mode)
  • Sidebar: Flat or blue gradient → ink black with copper active state (no rainbow sidebar)
  • Texture: Subtle grain overlay + restrained shadows instead of glow on every primary button

Recommended tokens

Fraunces — headlines
IBM Plex Sans — body, buttons, forms
IBM Plex Mono — 87 · TOP · OCR

Motion & layout

  • Keep your fadeIn page swap; add one orchestrated rise on podium + first card (see mock below)
  • Prefer 12–16px radius; avoid mixing 8px, 10px, 14px without reason
  • Let evidence blocks use a left copper border (not indigo) to tie to “human review”
  • Score ring optional: large mono numeral often reads clearer for recruiters scanning a list
